# หลักการทำงานของ VLA (Vision-Language-Action) — ฉบับละเอียด เข้าใจง่าย

เอกสารนี้อธิบายตั้งแต่พื้นฐานที่สุด สำหรับคนที่ไม่มีความรู้เรื่องหุ่นยนต์หรือ AI
มาก่อนเลย โดยใช้บริบทของโปรเจคเรา (หุ่น Unitree G1 หยิบของวางกล่อง ด้วย VLA
ชื่อ NVIDIA Isaac GR00T) เป็นตัวอย่างตลอดทั้งเอกสาร

> อ่านเรียงจากบนลงล่างได้เลย แต่ละหัวข้อต่อยอดจากหัวข้อก่อนหน้า

---

## 0. ปูพื้น: หุ่นยนต์ "คิด" ยังไง?

ลองนึกถึงตอนคุณหยิบแก้วน้ำบนโต๊ะ สมองคุณทำงานเป็นวงจรโดยไม่รู้ตัว:

1. **ตาเห็น** แก้ว (อยู่ตรงไหน ไกลแค่ไหน)
2. **สมองสั่ง** มือให้เอื้อมไป
3. **มือขยับ** เข้าใกล้แก้ว
4. **ตาเห็นใหม่** ว่ามือใกล้แก้วขึ้น
5. สมองปรับ สั่งมือกำ
6. ... วนไปจนกำแก้วได้

หุ่นยนต์ก็ทำแบบเดียวกันเป๊ะ เพียงแต่เราต้องเขียน "สมอง" ให้มัน — สมองนั้นเรียกว่า
**Policy** (นโยบาย) และในโปรเจคเรา สมองตัวนี้คือ **VLA**

**คำถามหลักของทั้งวงการ:** จะทำ "สมอง" ที่ดูภาพแล้วสั่งมือให้ทำงานถูกได้ยังไง?
คำตอบมีหลายวิธี เราจะเล่าทีละอย่าง

## 1. วงจรหัวใจ: "เห็น → คิด → ทำ" (closed loop)

```
   ┌────────────────────────────────────────────────────┐
   │                     (วนกลับ)                        │
   ▼                                                    │
[Observation] ─→ [Policy / VLA] ─→ [Action] ─→ [หุ่นขยับจริง]
  หุ่นเห็นอะไร       สมองคิด         หุ่นจะทำอะไร    โลกเปลี่ยนไป
```

- **Observation** = "สิ่งที่หุ่นรับรู้ ณ ขณะนั้น" (input ของสมอง)
- **Policy** = "สมอง" ที่แปลง observation ให้เป็นคำสั่ง
- **Action** = "คำสั่งที่จะทำ" (output ของสมอง)
- พอหุ่นทำ action → โลกเปลี่ยน → หุ่นเห็นภาพใหม่ → วนกลับไปข้อ 1

คำว่า **closed loop** (วงจรปิด) หมายถึง "หุ่นเห็นผลของการกระทำตัวเอง แล้วปรับตาม"
— ตรงข้ามกับ **open loop** (วงจรเปิด) ที่ทำตามแผนที่วางไว้ล่วงหน้าโดยไม่สนว่าผล
เป็นยังไง (เดี๋ยวอธิบายเพิ่มในหัวข้อ evaluation)

**ตัวเลขสำคัญ:** วงจรนี้วนเร็วมาก ในหุ่นจริงมักวน ~30 ครั้งต่อวินาที (30 FPS)
คือทุก ~0.03 วินาที หุ่นเห็นภาพใหม่และปรับการเคลื่อนไหว

## 2. Observation คืออะไร — เจาะลึกทีละส่วน

Observation คือ "ทุกอย่างที่หุ่นรู้ ณ วินาทีนั้น" ในโปรเจคเรามี 3 ส่วน:

### 2.1 Vision (การมองเห็น) — ภาพจากกล้อง

หุ่นเรามี **กล้อง 3 ตัว** ที่ให้มุมมองต่างกัน (เหมือนมีตาหลายคู่):

| กล้อง | ติดตรงไหน | เห็นอะไร |
| --- | --- | --- |
| `cam_left_high` | หัว/มุมสูง | ภาพรวมทั้งฉาก (โต๊ะ ของ กล่อง) |
| `cam_left_wrist` | ข้อมือซ้าย | ระยะใกล้ตอนมือซ้ายเอื้อม |
| `cam_right_wrist` | ข้อมือขวา | ระยะใกล้ตอนมือขวาเอื้อม |

- ทำไมต้องหลายกล้อง? กล้องหัวเห็นภาพรวมแต่พอมือบังของก็มองไม่เห็น กล้องข้อมือ
  ช่วยเห็นตอนจะกำของ (เหมือนคนมองมือตัวเองตอนหยิบของเล็กๆ)
- ภาพแต่ละกล้องขนาด **224×224 pixel** — สำหรับคอมพิวเตอร์ ภาพคือตารางตัวเลข
  (แต่ละ pixel มีค่าสี แดง-เขียว-น้ำเงิน) ดังนั้น 1 ภาพ = 224×224×3 = ~150,000 ตัวเลข

### 2.2 State / Proprioception (รู้ตำแหน่งตัวเอง)

**Proprioception** (อ่านว่า โพร-พรี-โอ-เซป-ชัน) = ความสามารถรู้ว่าร่างกายตัวเองอยู่
ท่าไหน โดยไม่ต้องมอง ลองหลับตาแล้วแตะปลายจมูก — คุณทำได้เพราะสมองรู้ตำแหน่งแขน
ตัวเองตลอดเวลา นั่นคือ proprioception

หุ่นก็ต้องมี — มัน "รู้" ว่าข้อต่อแต่ละอันบิดอยู่กี่องศา ในโปรเจคเราคือ **16 ตัวเลข**:

| ตำแหน่ง | ข้อต่อ | จำนวน |
| --- | --- | --- |
| แขนซ้าย | ไหล่ (3 ทิศ) + ศอก + ข้อมือ (3 ทิศ) | 7 |
| แขนขวา | เหมือนซ้าย | 7 |
| gripper ซ้าย | มือหนีบ (เปิด/ปิด) | 1 |
| gripper ขวา | มือหนีบ (เปิด/ปิด) | 1 |
| **รวม** | | **16** |

แต่ละตัวเลขคือ "มุมองศา" ของข้อต่อนั้น (เช่น ศอกงอ 90°) — หุ่นรู้ค่าพวกนี้จาก
เซนเซอร์ที่ข้อต่อ (encoder)

### 2.3 Language (คำสั่งภาษา)

นี่คือส่วนที่ทำให้ VLA พิเศษ — หุ่นรับ **คำสั่งเป็นข้อความภาษาอังกฤษ** เช่น:

- `"Pick up the red cup on the table."` (หยิบแก้วแดงบนโต๊ะ)
- `"Place the red wooden block into the yellow box."` (วางบล็อกแดงลงกล่องเหลือง)

หุ่นตัวเดียวกัน ถ้าให้คำสั่งต่างกัน → ควรทำงานต่างกัน นี่คือความหมายของ
**"สั่งด้วยคำสั่ง"** ที่เราต้องการ

### สรุป observation

ทุกๆ 1 จังหวะ หุ่นรับ observation = **{ ภาพ 3 กล้อง + มุมข้อต่อ 16 ค่า + คำสั่ง
1 ประโยค }** แล้วส่งเข้า "สมอง" (VLA) เพื่อคิดว่าจะทำอะไรต่อ

## 3. Action คืออะไร — เจาะลึก

**Action** = คำสั่งที่สมองส่งให้ร่างกายทำ ในโปรเจคเราคือ **16 ตัวเลข** เหมือน
state เป๊ะ (แขนซ้าย 7 + แขนขวา 7 + gripper 2) แต่ความหมายต่างกัน:

- **State** = "ตอนนี้ข้อต่ออยู่มุมไหน" (ปัจจุบัน)
- **Action** = "อยากให้ข้อต่อไปมุมไหน/ขยับยังไง" (สิ่งที่จะทำต่อไป)

### 3.1 Action มี 2 แบบ (สำคัญมาก)

**แบบ Absolute (ตำแหน่งเป้าหมาย):** บอกตรงๆ ว่า "ไปมุม 45°"
- เหมือนบอก GPS ว่า "ไปที่พิกัดนี้"
- โปรเจคเราใช้กับ **gripper** — เพราะ gripper มีแค่ 2 สถานะหลัก (เปิด/ปิด) บอก
  ตำแหน่งเป้าตรงๆ ชัดเจนกว่า

**แบบ Relative / Delta (ส่วนต่าง):** บอกว่า "ขยับเพิ่มอีก 5° จากตอนนี้"
- เหมือนบอกว่า "เดินไปข้างหน้าอีก 3 ก้าว" (ไม่สนว่าตอนนี้อยู่ไหน)
- โปรเจคเราใช้กับ **แขน** — เพราะการบอก "ขยับเพิ่มเท่าไหร่" ทำให้ policy ยืดหยุ่น
  กว่า (เริ่มจากท่าไหนก็ปรับได้ถูก) เรียกว่า generalize ดีกว่า

### 3.2 Action Chunk (การทำนายเป็นชุด) — แนวคิดสำคัญของ VLA

นี่คือจุดที่ VLA ฉลาด แทนที่จะคิดทีละจังหวะ ("ตอนนี้ขยับแขนไปนิดนึง") VLA จะ
**วางแผนล่วงหน้า 16 จังหวะพร้อมกัน** เรียกว่า action chunk (chunk = ก้อน/ชุด)

เปรียบเทียบ:
- **ไม่มี chunk (คิดทีละก้าว):** เหมือนเดินโดยมองแค่พื้นตรงหน้า 1 ก้าว —
  ต้องหยุดคิดทุกก้าว ช้าและกระตุก
- **มี chunk (วางแผน 16 ก้าว):** เหมือนมองทางล่วงหน้าแล้วเดินลื่นๆ 16 ก้าว
  ค่อยมองใหม่ — ราบรื่นและเร็ว

**ตัวเลขในโปรเจคเรา:** action horizon = 16 หมายถึง VLA ทำนายการเคลื่อนไหว 16
จังหวะอนาคตในการคิด 1 ครั้ง แล้วหุ่นทยอยทำ ทำให้:
- เคลื่อนไหวลื่น (ไม่กระตุก)
- ไม่ต้องคิดทุกจังหวะ (คิด 1 ครั้งใช้ได้หลายจังหวะ = เร็วขึ้น)

## 4. Policy / VLA ทำงานยังไงข้างใน

**Policy** คือฟังก์ชันคณิตศาสตร์ขนาดยักษ์ (neural network / โครงข่ายประสาทเทียม)
ที่รับ observation แล้วคำนวณออกมาเป็น action

VLA ของเรา (GR00T) ข้างในมี 2 ส่วนหลัก:

### 4.1 ส่วน "เข้าใจภาพ + ภาษา" (Vision-Language Model / VLM)

- ใช้โมเดลชื่อ **Qwen2.5-VL / Cosmos-Reason** (โมเดล AI ที่ดูภาพและอ่านภาษาได้)
- หน้าที่: ดูภาพ 3 กล้อง + อ่านคำสั่ง → "เข้าใจ" ว่าฉากมีอะไร และต้องทำอะไร
- เหมือนส่วนที่ตอบว่า "อ๋อ มีบล็อกแดงกับกล่องเหลือง และเขาสั่งให้เอาบล็อกใส่กล่อง"

### 4.2 ส่วน "สร้างการเคลื่อนไหว" (Action Head — ใช้ Diffusion)

หลังเข้าใจแล้ว ต้องแปลงเป็น action 16 ตัวเลข × 16 จังหวะ ส่วนนี้ใช้เทคนิคชื่อ
**Diffusion** (ดิฟฟิวชัน)

**Diffusion คืออะไร (อธิบายแบบง่ายสุด):**
- เป็นเทคนิคเดียวกับที่ AI ใช้สร้างรูปภาพ (เช่น Midjourney, Stable Diffusion)
- หลักการ: เริ่มจาก "ความมั่ว" (noise สุ่มๆ) แล้วค่อยๆ "ขัดเกลา" ให้ชัดขึ้นทีละรอบ
- เหมือนปั้นดินจากก้อนมั่วๆ ค่อยๆ แต่งจนเป็นรูป
- VLA เราใช้สร้าง "การเคลื่อนไหว" แทนรูปภาพ: เริ่มจากการขยับมั่วๆ แล้วขัดเกลา
  จนได้ท่าหยิบของที่ถูกต้อง
- โปรเจคเราขัดเกลา **4 รอบ** (denoising steps = 4) — ยิ่งหลายรอบยิ่งเนียนแต่ช้าลง

## 4.5 เริ่มต้นแต่แรกทำอะไร — ภาพรวม pipeline ทั้งหมด

ถ้าเริ่มจากศูนย์ ลำดับงานทั้งหมดเป็นแบบนี้ (แต่ละขั้นต่อยอดจากขั้นก่อน):

```
ขั้น 1: เก็บตัวอย่าง (Demonstration)
        คนบังคับหุ่นทำงานให้ดูซ้ำๆ (teleoperation)
        → ได้ dataset 216 demos (ภาพ + มุมข้อต่อ + คำสั่ง ทุกจังหวะ)
              │
              ▼
ขั้น 2: เทรน (Imitation Learning)
        ให้ policy ดูตัวอย่างแล้วเลียนแบบ เทรน 2000 รอบบน GPU
        → loss ลดจาก 1.1 → 0.11 (เรียนรู้ได้ดี)
              │
              ▼
ขั้น 3: ได้ Checkpoint (ไฟล์สมองที่เรียนแล้ว)
        → checkpoint-2000 พร้อมใช้ทำนาย action
              │
              ▼
ขั้น 4: ทดสอบ + นำไปใช้
        ตรวจว่าเก่งจริงไหม (open-loop eval) แล้วเชื่อมเข้าซิม/หุ่นจริง
        → ตอนนี้เราอยู่ตรงนี้
```

**การป้อนข้อมูลจริงหน้าตาเป็นยังไง:** ทุกๆ 1 จังหวะ เราสร้าง observation
เป็น dictionary แบบนี้ส่งเข้า policy:

```
observation = {
  "video.cam_high":       ภาพ 224×224×3 (กล้องหัว),
  "video.cam_left_wrist": ภาพ 224×224×3 (ข้อมือซ้าย),
  "video.cam_right_wrist":ภาพ 224×224×3 (ข้อมือขวา),
  "state.left_arm":       [7 ตัวเลข = มุมแขนซ้าย],
  "state.right_arm":      [7 ตัวเลข = มุมแขนขวา],
  "state.left_gripper":   [1 ตัวเลข],
  "state.right_gripper":  [1 ตัวเลข],
  "annotation.human.task_description": "Place the red block into the yellow box"
}

action = policy.get_action(observation)
# ได้ action chunk กลับมา = 16 จังหวะ × 16 ตัวเลข
```

จากนั้นเอา action ไปสั่งข้อต่อหุ่น → หุ่นขยับ → สร้าง observation ใหม่ → วนซ้ำ

## 5. หุ่นเรียน "สมอง" นี้มาได้ยังไง — Training

Policy ไม่ได้เก่งมาตั้งแต่เกิด ต้อง "เรียน" (train) ก่อน มี 2 วิธีใหญ่:

### 5.1 Imitation Learning (เรียนจากการเลียนแบบ) — วิธีที่เราใช้

- ให้คนบังคับหุ่นทำงานให้ดู หลายๆ ครั้ง (เรียกว่า **demonstration** หรือ demo)
- โปรเจคเรามี **216 demos** ที่คนบังคับหุ่น (teleoperate) หยิบของวางกล่องสำเร็จ
- policy ดู demo พวกนี้แล้ว "เลียนแบบ" — พอเห็นภาพแบบนี้ คนขยับแขนแบบนี้ ก็ทำตาม
- วิธีเลียนแบบ action ตรงๆ นี้เรียก **Behavior Cloning (BC)**
- ข้อดี: เรียนเร็ว ไม่ต้องลองผิดลองถูกเอง (เพราะมีตัวอย่างที่ถูกอยู่แล้ว)
- ข้อเสีย: ทำได้แค่สิ่งที่เห็นใน demo ถ้าเจอสถานการณ์แปลกใหม่อาจงง

### 5.2 Reinforcement Learning (RL — เรียนจากลองผิดลองถูก)

- ไม่มีตัวอย่าง ให้หุ่นลองทำเองในซิม แล้วให้ "รางวัล" (reward) เมื่อทำถูก
- เหมือนฝึกสุนัข ทำถูกให้ขนม ทำผิดไม่ให้ หุ่นค่อยๆ เรียนว่าทำยังไงได้ reward เยอะ
- **เราลองวิธีนี้ก่อน** (task ชื่อ Lift-Cube, Place-Box) แต่**ล้มเหลว** — เพราะการ
  หยิบของด้วยมือหลายนิ้วจาก "การลองมั่วๆ" มันยากเกิน หุ่นลองเท่าไหร่ก็จับof ไม่ได้
  สักที (reward ไม่ขึ้น = ไม่เรียนรู้) เรียกอาการนี้ว่า **plateau** (ตัน)
- เลยเปลี่ยนมาใช้ imitation (5.1) ที่มี demo สำเร็จอยู่แล้ว → ข้ามปัญหานี้ไปได้

### สรุปว่าทำไมเลือก Imitation

RL ให้หุ่นค้นพบวิธีหยิบเอง = ยากมาก (เหมือนให้เด็กเรียนขี่จักรยานโดยไม่มีใครสอน
ล้มเป็นพันครั้ง) ส่วน Imitation = มีคนขี่ให้ดู 216 รอบแล้วเลียนแบบ = ง่ายกว่ามาก

## 6. รู้ได้ยังไงว่า policy เก่งหรือไม่ — Evaluation

เทรนเสร็จได้ไฟล์โมเดล (เรียก **checkpoint**) แล้วต้องทดสอบ มี 2 ระดับ:

### 6.1 Open-loop evaluation (ทดสอบแบบวงจรเปิด) — ที่เราทำแล้ว

- เอา observation จริงจาก demo (ที่รู้คำตอบถูกอยู่แล้ว) มาป้อน policy
- ดูว่า action ที่ policy ทำนาย **ตรงกับ action จริงที่คนทำไหม**
- วัดด้วย **MSE / MAE** (ตัวเลขบอกว่า "ทำนายห่างจากคำตอบจริงแค่ไหน" ยิ่งต่ำยิ่งดี)
- **ผลของเรา: MSE 0.21, MAE 0.17** — แปลว่าทำนายใกล้เคียงคำตอบจริง = policy
  เรียนรู้ได้ (ไม่ได้มั่ว)
- เรียก "open-loop" เพราะ observation มาจาก demo ตายตัว ไม่ใช่จากการกระทำของ
  policy เอง (policy ไม่ได้คุมสถานการณ์จริง)

### 6.2 Closed-loop evaluation (ทดสอบแบบวงจรปิด) — ขั้นต่อไป

- ให้ policy **คุมหุ่นจริงๆ** (ในซิมหรือหุ่นจริง): action ของมันทำให้โลกเปลี่ยน
  แล้วมันต้องเห็นผลของตัวเองและทำต่อ
- ยากและจริงกว่า เพราะถ้าทำพลาดนิดเดียว สถานการณ์จะเพี้ยนไปจาก demo แล้วอาจ
  พลาดหนักขึ้น (เรียก **compounding error** — ความผิดพลาดสะสม)
- นี่คือสิ่งที่เรากำลังจะทำต่อ (เชื่อม VLA เข้า mjlab sim)

**เปรียบเทียบให้เห็นภาพ:** open-loop เหมือนสอบข้อเขียน (มีเฉลย เทียบคำตอบได้);
closed-loop เหมือนสอบขับรถจริง (พลาดแล้วต้องแก้สถานการณ์เอง)

## 7. นำไปใช้จริง — เส้นทางจาก demo สู่หุ่นจริง

```
1. Dataset (คนบังคับหุ่น 216 รอบ)
        │  เอาไปเทรน (imitation)
        ▼
2. VLA checkpoint (สมองที่เรียนแล้ว)   ← ตอนนี้เราอยู่ตรงนี้
        │
   ┌────┴─────────────────────┐
   ▼                          ▼
3a. ทดสอบในซิม (mjlab)     3b. หุ่นจริง
   (กำลังจะทำ)              (กล้อง+มอเตอร์จริง)
```

### ทำไมต้องทดสอบในซิมก่อน?

- **ปลอดภัย** — หุ่นจริงราคาแพง ถ้า policy สั่งมั่วอาจพัง/ล้ม
- **เร็ว** — reset ซิมได้ทันที ไม่ต้องจัดฉากใหม่
- **ถูก** — ไม่เปลืองหุ่นจริง

ถ้า policy ทำงานดีในซิม → ค่อยเอาไปลองหุ่นจริง

### ความท้าทายที่จะเจอตอนใช้จริง

| ปัญหา | คืออะไร | ตัวอย่าง |
| --- | --- | --- |
| **Sim-to-real gap** | ซิมไม่เหมือนจริง 100% | แสง/เงา/physics ในซิมต่างจากจริง policy เลยงกๆ |
| **Distribution shift** | เจอสิ่งที่ต่างจากตอนเทรน | ของสีต่าง มุมกล้องเพี้ยน → policy สับสน |
| **Compounding error** | ผิดนิดเดียวสะสมใหญ่ | พลาดจังหวะแรก ทำให้จังหวะถัดไปเพี้ยนตาม |

## 8. 2 โหมดการใช้งาน (เป้าหมายของโปรเจค)

VLA ตัวเดียวทำได้ 2 โหมด ต่างกันแค่ "จะเปลี่ยนคำสั่งไหม":

### โหมดที่ 1: สั่งด้วยคำสั่ง (Language-conditioned)

- คนพิมพ์คำสั่งต่างกัน → หุ่นทำงานต่างกัน
- เช่น พิมพ์ "หยิบแก้ว" หุ่นหยิบแก้ว, พิมพ์ "วางบล็อกลงกล่อง" หุ่นทำอีกอย่าง
- ใช้ policy ตัวเดิม แค่เปลี่ยนข้อความ language ใน observation

### โหมดที่ 2: อัตโนมัติ (Autonomous)

- ตั้งคำสั่งไว้คงที่ 1 อย่าง แล้วปล่อยให้หุ่นทำเองจนจบ (closed-loop)
- เช่น ตั้ง "วางบล็อกลงกล่อง" แล้วหุ่นทำวนไปเองจนสำเร็จ ไม่ต้องสั่งซ้ำ

**ความสวยของ VLA:** ตัวเดียวทำได้หลายงานด้วยการเปลี่ยนคำสั่ง (ต่างจากหุ่นสมัยก่อน
ที่ 1 โปรแกรม = 1 งาน)

## 9. คำศัพท์รวม (พจนานุกรมย่อ)

| ศัพท์ | ความหมายสั้นๆ |
| --- | --- |
| **Policy** | "สมอง" ที่แปลง observation → action |
| **VLA** | สมองที่รับภาพ + ภาษา แล้วสั่ง action |
| **Observation (obs)** | สิ่งที่หุ่นรับรู้ (ภาพ + มุมข้อต่อ + คำสั่ง) |
| **Action** | คำสั่งที่หุ่นจะทำ (16 ตัวเลข = มุมข้อต่อ) |
| **Proprioception** | หุ่นรู้ตำแหน่งข้อต่อตัวเอง |
| **Action chunk / horizon** | ทำนายหลายจังหวะพร้อมกัน (เรา = 16) |
| **Absolute / Relative action** | สั่งตำแหน่งเป้า / สั่งส่วนต่าง |
| **Diffusion** | เทคนิคสร้าง action จาก noise (ขัดเกลาทีละรอบ) |
| **Inference** | การที่โมเดลทำนาย (ใช้งานจริง ตรงข้ามกับ train) |
| **Training** | การสอนโมเดลให้เก่ง |
| **Checkpoint** | ไฟล์โมเดลที่เซฟไว้ |
| **Imitation Learning** | เรียนจากการเลียนแบบ demo |
| **Behavior Cloning (BC)** | เลียนแบบ action ตรงๆ |
| **RL** | เรียนจากลองผิดลองถูก + reward |
| **Demonstration (demo)** | ตัวอย่างที่คนบังคับหุ่นทำสำเร็จ |
| **Rollout** | รัน policy 1 รอบเต็ม(เริ่มจนจบงาน) |
| **Open-loop** | ทดสอบเทียบ action กับคำตอบจาก demo |
| **Closed-loop** | policy คุมสถานการณ์จริง เห็นผลตัวเอง |
| **MSE / MAE** | วัดความห่างของ action ทำนาย vs จริง (ต่ำ=ดี) |
| **Plateau** | อาการเรียนไม่ขึ้น (ตัน) |
| **Sim-to-real gap** | ซิมกับของจริงต่างกัน |
| **Compounding error** | ความผิดพลาดสะสมใน closed-loop |
| **Embodiment** | "ร่าง" ของหุ่น (แขน/มือ/DOF ที่มี) |
| **DOF** | Degrees of Freedom = จำนวนข้อต่อที่ขยับได้อิสระ |
| **Gripper** | มือหนีบ (เปิด/ปิด จับของ) |
| **Teleoperation** | คนบังคับหุ่นระยะไกล (เพื่อเก็บ demo) |
